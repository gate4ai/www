# gate4.ai — сайт: требования

> Версия 0.2, 2026-10-18 (0.1 — 2026-10-14, сайт на Rust). Сайт на https://gate4.ai: установщики, продающий лендинг, каталог коннекторов. Продукт описан в [спецификации](../gate4ai/docs/specification.md), инструкция для пользователя — в [README ядра](../gate4ai/README.md).

## Что должен делать сайт

1. **Раздавать установщики для каждой ОС**, чтобы gate4ai ставился одной командой:
   - macOS и Linux: `curl -fsSL https://gate4.ai/install.sh | sh`
   - Windows (PowerShell): `irm https://gate4.ai/install.ps1 | iex`
2. **Продающий лендинг** на главной странице.
3. **Каталог коннекторов**, собранный из [registry](https://github.com/gate4ai/registry).
4. **Написан на Go.**

README ядра уже ссылается на `https://gate4.ai/install.sh`, `https://gate4.ai/install.ps1` и `https://gate4.ai/connectors`. Пока сайта нет, эти команды и ссылки не работают.

## 1. Установщики

### Откуда брать бинарники

Релизы ядра — на [GitHub Releases](https://github.com/gate4ai/gate4ai/releases) (GoReleaser, тег `v*`). Имена файлов:

| Файл | Что внутри |
|---|---|
| `gate4ai_<версия>_<os>_<arch>.tar.gz` (Windows — `.zip`) | `gate4ai`, LICENSE, README.md, docs/ |
| `gate4ai-tray_<версия>_<os>_<arch>.tar.gz` (Windows — `.zip`) | `gate4ai-tray` для linux и windows |
| `gate4ai-tray_<версия>_darwin_<arch>.tar.gz` | трей для macOS: внутри каталог `gate4ai-tray_<версия>_darwin_<arch>/` |
| `checksums.txt` + `.sig` + `.pem` | sha256 всех архивов, кроме трея macOS; подпись cosign (keyless) |
| `tray-darwin-checksums.txt` + `.sig` + `.pem` | sha256 архивов трея macOS |

`os` — `linux`, `darwin`, `windows`; `arch` — `amd64`, `arm64`.

### Требования к `install.sh` (macOS, Linux)

- POSIX `sh`, без bash-измов; из зависимостей — только `curl` или `wget`, `tar`, `sha256sum` или `shasum`.
- Определяет ОС (`uname -s`) и архитектуру (`uname -m`: `x86_64`/`amd64` → `amd64`, `aarch64`/`arm64` → `arm64`). Неподдерживаемая платформа — понятная ошибка со ссылкой на Releases.
- Версия: последняя по умолчанию; `GATE4AI_VERSION=v0.1.1` — конкретная.
- Скачивает архивы ядра и трея и `checksums.txt` (для трея macOS — `tray-darwin-checksums.txt`) и сверяет sha256. Если сумма не совпала, ничего не ставит и завершается с ошибкой. Если в системе есть `cosign`, дополнительно проверяет подпись `checksums.txt` (идентичность `^https://github.com/gate4ai/gate4ai/`, issuer `https://token.actions.githubusercontent.com`).
- Каталог установки: `GATE4AI_INSTALL_DIR`, иначе `~/.local/bin`. `sudo` сам не вызывает. Если каталога нет в `PATH`, печатает, как его добавить.
- Повторный запуск обновляет установленную версию. Конфигурацию и данные не трогает. Daemon запускает только с `GATE4AI_START=1`: тогда вызывает `gate4ai service install` (daemon сейчас и при каждом входе; systemd --user / launchd, трей — в автозапуск входа).
- В конце печатает версию (`gate4ai --version`) и следующие шаги со ссылкой на README («Первый запуск»): `gate4ai service install` (если автозапуск не включён) и `gate4ai ui`; `gate4ai ui` в терминале сам запускает daemon, если он не работает.
- Весь скрипт обёрнут в функцию, которая вызывается последней строкой: оборванная загрузка `curl | sh` не выполняет половину скрипта.
- Трей ставится по умолчанию; `GATE4AI_NO_TRAY=1` — без трея (серверы без графики).

### Требования к `install.ps1` (Windows)

- Windows PowerShell 5.1 и PowerShell 7; без прав администратора.
- Архитектура из `PROCESSOR_ARCHITECTURE` (`AMD64` → `amd64`, `ARM64` → `arm64`).
- Те же переменные `GATE4AI_VERSION`, `GATE4AI_INSTALL_DIR`, `GATE4AI_NO_TRAY`, `GATE4AI_START` (автозапуск — ключ `HKCU\…\Run`) и та же сверка sha256 (`Get-FileHash`).
- Каталог по умолчанию — `%LOCALAPPDATA%\Programs\gate4ai`; добавляется в `PATH` пользователя.

### Что отдаёт сайт

- `GET /install.sh` и `GET /install.ps1` — `text/plain; charset=utf-8`, `Cache-Control` с коротким сроком (минуты). Исходники скриптов лежат в этом каталоге (`www/install/`) и проверяются в CI: `shellcheck` и `PSScriptAnalyzer`.
- `GET /install` — страница для человека: команда под его ОС (по User-Agent, с переключателем) и ссылки на ручную установку.
- `GET /latest` — номер последней версии ядра текстом (`v0.1.1`). Сайт кэширует его из GitHub API, чтобы установщики не упирались в лимиты API GitHub: запрос `/latest` сверяет версию с GitHub, если последняя сверка старше минуты (условный запрос с ETag), — новый релиз виден через минуту, а не через 10. Установщики берут версию отсюда и только при недоступности сайта идут в GitHub.
- Сами бинарники сайт не хранит: установщики качают их с GitHub Releases. Если потом понадобится зеркало, это `GET /download/<версия>/<файл>` с теми же контрольными суммами.

## 2. Продающий лендинг

Аудитория (спецификация, «Для кого»): пользователи персональных AI-агентов (OpenClaw, Hermes, Claude.ai, ChatGPT, Claude Code), чаще всего не программисты. Им нужно понять, зачем это, и поставить gate4ai за минуту.

Содержание главной страницы:

1. **Первый экран:** что это одной фразой («страж для вашего компьютера: AI-агенты получают доступ только к тому, что вы разрешили») и команда установки под ОС посетителя с кнопкой «скопировать».
2. **Проблема:** агентам дают слишком много (почта, браузер, shell целиком); prompt injection превращается в действия; агенты отчитываются «сделано», хотя ничего не сделали.
3. **Как работает:** агент → gate4ai (правила: разрешить, запретить или спросить вас) → коннектор; пароли агент не видит; у каждого действия есть доказательство в журнале.
4. **Сценарии:** «пусть агент пишет письма только бухгалтеру», «читать заметки можно, менять — только с моего подтверждения в Telegram», «оплатить ЖКХ, но не больше N в месяц».
5. **Работает с вашими агентами:** Claude.ai, ChatGPT, Claude Code, OpenClaw, Hermes (через MCP, CLI, skill).
6. **Коннекторы:** несколько карточек из каталога и ссылка на `/connectors`.
7. **Открытый код и доверие:** исходники на GitHub, лицензии, подписанные релизы и коннекторы, работа локально без облака.
8. **Подвал:** GitHub, документация, спецификация, контакты, безопасность (`SECURITY.md`).

Утверждения на лендинге должны совпадать с тем, что продукт делает сейчас.

## 3. Каталог коннекторов

- **Источник:** `https://raw.githubusercontent.com/gate4ai/registry/main/index.json` и `index.json.sig`. Сайт проверяет подпись ключом registry (`ed25519:yDcbQuNCGqSqHSt08HdvW5/fNyWRW8FIXtKiL91hqtw=`, тот же, что в README ядра) теми же правилами, что `gate4ai registry check`. Индекс с неверной подписью не показывается: остаётся последний проверенный.
- **Обновление:** периодически (раз в несколько минут) и по запросу из CI registry (webhook) после слияния.
- **`GET /connectors`** — список с поиском по имени и описанию и с фильтром по уровню доверия (`verified`, `publisher`, `community`). Карточка: имя, описание, издатель, уровень доверия, последняя версия.
- **`GET /connectors/<имя>`** — страница коннектора:
  - описание, издатель, уровень доверия и что он значит, лицензия, ссылка на исходники (`repo`);
  - **возможности** (`capabilities`) человеческим языком: «ходит в сеть только на IMAP/SMTP из ваших настроек», «получает пароль только для этого адреса»; рядом — исходная строка;
  - версии и отозванные версии с причиной;
  - команда установки: `gate4ai connectors install <имя>`.
- **`GET /connectors.json`** — тот же индекс как есть, для внешних инструментов.

## 4. Технические требования

- **Язык — Go** (версия из `go.mod`). Один бинарник отдаёт HTML, скрипты установки и API. Стек: стандартная библиотека — `net/http`, шаблоны `html/template` (разбираются при старте, каждый проверяется тестами), шаблоны и статика встраиваются через `embed`; формат индекса registry и проверка его подписи — пакет `sdk-go/registry` (те же правила, что у ядра).
- **Страницы рендерятся на сервере** и работают без JavaScript. JS допускается только для мелочей: «скопировать», поиск в каталоге.
- **Приватность:** без трекеров, сторонних скриптов, шрифтов и cookies. Для продукта о безопасности это часть позиционирования.
- **Языки:** английский (основная аудитория глобальная) и русский; язык выбирается по `Accept-Language`, есть переключатель, отдельные пути `/ru/…`.
- **Скорость:** страница меньше 100 КБ без картинок; адаптивная вёрстка; доступность по WCAG 2.2 AA.
- **Эксплуатация:** сайт слушает только HTTP на `127.0.0.1:8080`, TLS (Let's Encrypt) завершает Caddy; служба — контейнер в Compose-проекте (`deploy/compose.yaml`), `/healthz`, логи без IP-адресов посетителей, конфигурация через переменные окружения. Индекс registry и `/latest` — только в памяти, каталога состояния нет.
- **Тесты:** `go test` проверяет маршруты, проверку подписи индекса (верная, неверная, подменённая; здесь и в `sdk-go/registry`), разбор User-Agent и `/latest`, бюджет страниц; `install.sh` гоняется в CI на Linux и macOS, `install.ps1` — на Windows; `gofmt`, `go vet`.

## 5. Хостинг (решено 2026-10-14)

Сайт работает на сервере relay (136.148.221.24) за тем же портом 443. Relay маршрутизирует по SNI: `gate4ai-relay --route gate4.ai=127.0.0.1:8444 --route www.gate4.ai=127.0.0.1:8444` пробрасывает соединения **без расшифровки** ([протокол relay](../relay/docs/protocol.md)) на Caddy из стека наблюдаемости relay — тот же, что обслуживает `grafana.gate4.ai` ([relay/docs/observability.md](../relay/docs/observability.md)).

- **HTTPS завершает Caddy рядом с сайтом, а не relay.** Relay остаётся L4-маршрутизатором и ни для кого не расшифровывает трафик: это тот же принцип, что и для устройств. У relay нет ключей сайта, а сайт не зависит от релизов relay. (Решено 2026-10-18: до этого TLS и ACME были в самом сайте на `127.0.0.1:8443`.)
- **Сертификаты** на `gate4.ai` и `www.gate4.ai` получает Caddy через ACME **TLS-ALPN-01**: проверка Let's Encrypt приходит на 443 с SNI `gate4.ai` и через маршрут попадает на Caddy. Порт 80 для этого не нужен.
- **Сайт слушает** только HTTP на `127.0.0.1:8080` (Compose-проект `gate4ai-www`, сеть хоста) и не открыт наружу напрямую; Caddy проксирует на него. IP посетителя сайт не видит (relay не передаёт PROXY protocol), это совпадает с требованием не писать IP в логи.
- **Порт 80** (редирект на HTTPS) занят только во время продления сертификата relay (`certbot --standalone`). Если сайту понадобится редирект с 80, certbot переводится на `--webroot`, а каталог `/.well-known/acme-challenge/` отдаёт сайт.
- **DNS:** `gate4.ai` (A 136.148.221.24, AAAA `2a13:7c82:128:48::`) и `www.gate4.ai` (через `*.gate4.ai`) указывают на relay — переключено 2026-10-15. Сертификат — на оба имени, `www` сайт перенаправляет на `gate4.ai` (308, `GATE4AI_WWW_CANONICAL_HOST`).

## Открытые вопросы

- **Лицензия** кода сайта. Репозиторий решён (2026-10-14): приватный `gate4ai/www`, без лицензии; записан в [publishing.md](../gate4ai/docs/publishing.md).
- **Тексты лендинга и визуальный стиль:** нужен ли бренд-гайд и кто утверждает тексты.
- **Каталог в продукте:** показывать ли со временем каталог в Web UI gate4ai по тому же индексу.

## Готово, когда

- `curl -fsSL https://gate4.ai/install.sh | sh` на чистых Linux (amd64, arm64) и macOS (arm64), а также `irm https://gate4.ai/install.ps1 | iex` на чистой Windows ставят последний релиз и печатают версию; подменённый архив не ставится.
- Главная страница открывается без JS и показывает команду установки под ОС посетителя.
- `/connectors` показывает все коннекторы из подписанного индекса registry, а страница коннектора — его возможности и команду установки.
- Сайт собирается `go build` в один бинарник (образ `ghcr.io/gate4ai/www:<sha>`); тесты и линтеры проходят в CI.
