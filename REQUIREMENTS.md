# gate4.ai — сайт: требования

> Сайт на https://gate4.ai: установщики, продающий лендинг, каталог коннекторов. Продукт описан в [спецификации](../gate4ai/docs/specification.md), инструкция для пользователя — в [README ядра](../gate4ai/README.md).

## Что должен делать сайт

1. **Раздавать установщики для каждой ОС**, чтобы gate4ai ставился одной командой:
   - macOS и Linux: `curl -fsSL https://gate4.ai/install.sh | sh`
   - Windows (PowerShell): `irm https://gate4.ai/install.ps1 | iex`
2. **Продающий лендинг** на главной странице.
3. **Каталог коннекторов**, собранный из [registry](https://github.com/gate4ai/registry).
4. **Написан на Go.**

README ядра ссылается на `https://gate4.ai/install.sh`, `https://gate4.ai/install.ps1` и `https://gate4.ai/connectors`.

## 1. Установщики

### Откуда брать бинарники

Релизы ядра — на [GitHub Releases](https://github.com/gate4ai/gate4ai/releases) (GoReleaser, тег `v*`). Имена файлов:

| Файл | Что внутри |
|---|---|
| `gate4ai_<версия>_<os>_<arch>.tar.gz` (Windows — `.zip`) | `gate4ai`, LICENSE, README.md, docs/ |
| `gate4ai-tray_<версия>_<os>_<arch>.tar.gz` (Windows — `.zip`) | `gate4ai-tray` для linux и windows |
| `gate4ai-tray_<версия>_darwin_<arch>.tar.gz` | трей для macOS: внутри каталог `gate4ai-tray_<версия>_darwin_<arch>/` |
| `checksums.txt` + `.sig` + `.pem` | sha256 всех архивов, кроме трея macOS; подпись cosign (keyless) |
| `tray-darwin-checksums.txt` + `.sig` + `.pem` | sha256 архивов трея macOS |

`os` — `linux`, `darwin`, `windows`; `arch` — `amd64`, `arm64`.

### Требования к `install.sh` (macOS, Linux)

- POSIX `sh`, без bash-измов; из зависимостей — только `curl` или GNU `wget` (оба — только HTTPS и TLS 1.2+), `tar`, `sha256sum` или `shasum`.
- Определяет ОС (`uname -s`) и архитектуру (`uname -m`: `x86_64`/`amd64` → `amd64`, `aarch64`/`arm64` → `arm64`). Неподдерживаемая платформа — понятная ошибка со ссылкой на Releases.
- Версия: последняя по умолчанию; `GATE4AI_VERSION=v0.1.1` — конкретная.
- Скачивает архивы ядра и трея и `checksums.txt` (для трея macOS — `tray-darwin-checksums.txt`) и сверяет sha256. Если сумма не совпала, ничего не ставит и завершается с ошибкой. Если в системе есть `cosign`, дополнительно проверяет подпись `checksums.txt` (идентичность — только workflow релиза на теге: `^https://github.com/gate4ai/gate4ai/\.github/workflows/release\.yml@refs/tags/v`, issuer `https://token.actions.githubusercontent.com`).
- Каталог установки: `GATE4AI_INSTALL_DIR`, иначе `~/.local/bin`. `sudo` сам не вызывает. Если каталога нет в `PATH`, печатает, как его добавить.
- Повторный запуск обновляет установленную версию. Конфигурацию и данные не трогает.
- **Автозапуск по умолчанию:** вызывает `gate4ai service install` (daemon сейчас и при каждом входе; systemd --user / launchd, трей — в автозапуск входа); `service install` заодно перезапускает уже работающий daemon с новой версией. `GATE4AI_NO_START=1` — без автозапуска: тогда работающий daemon только перезапускается (`gate4ai daemon restart`). Неудача автозапуска установку не проваливает.
- **Мастер сразу:** если daemon работает, есть графическая сессия (Linux — задан `DISPLAY` или `WAYLAND_DISPLAY`; macOS — не по SSH), не задан `CI` и не задан `GATE4AI_NO_OPEN`, вызывает `gate4ai ui` — браузер открывает Web UI с мастером первого запуска. Неудача открытия установку не проваливает.
- В конце печатает версию (`gate4ai --version`), подсказку про `PATH` (если нужна) и **одну строку**: что мастер открыт в браузере, иначе `Next: gate4ai ui   # opens the setup wizard in your browser`. Вывод — на английском, как у CLI.
- Весь скрипт обёрнут в функцию, которая вызывается последней строкой: оборванная загрузка `curl | sh` не выполняет половину скрипта.
- Трей ставится по умолчанию; `GATE4AI_NO_TRAY=1` — без трея (серверы без графики).

### Требования к `install.ps1` (Windows)

- Windows PowerShell 5.1 и PowerShell 7; без прав администратора.
- Архитектура из `PROCESSOR_ARCHITECTURE` (`AMD64` → `amd64`, `ARM64` → `arm64`).
- Те же переменные `GATE4AI_VERSION`, `GATE4AI_INSTALL_DIR`, `GATE4AI_NO_TRAY`, `GATE4AI_NO_START` (автозапуск по умолчанию — ключ `HKCU\…\Run`), `GATE4AI_NO_OPEN` (графическая сессия на Windows есть всегда; не открывается и при заданном `CI`), та же последняя строка и та же сверка sha256 (`Get-FileHash`).
- Каталог по умолчанию — `%LOCALAPPDATA%\Programs\gate4ai`; добавляется в `PATH` пользователя.

### Что отдаёт сайт

- `GET /install.sh` и `GET /install.ps1` — `text/plain; charset=utf-8`, `Cache-Control` с коротким сроком (минуты). Исходники скриптов лежат в этом каталоге (`www/install/`) и проверяются в CI: `shellcheck` и `PSScriptAnalyzer`.
- `GET /install` — страница для человека: команда под его ОС (по User-Agent, с переключателем), что делает установщик, следующий шаг — `gate4ai ui` с кнопкой «скопировать» («откроется мастер: подключите ассистента, выберите папки и сайты, посмотрите на первое подтверждение»; README — второстепенной ссылкой), ручная установка и свёрнутый блок «Для администраторов» (`<details>`) с параметрами установщика, включая `GATE4AI_NO_START` и `GATE4AI_NO_OPEN`.
- `GET /latest` — номер последней версии ядра текстом (`v0.1.1`). Сайт кэширует его из GitHub API, чтобы установщики не упирались в лимиты API GitHub: запрос `/latest` сверяет версию с GitHub, если последняя сверка старше минуты (условный запрос с ETag), — новый релиз виден через минуту, а не через 10. Установщики берут версию отсюда и только при недоступности сайта идут в GitHub.
- Сами бинарники сайт не хранит: установщики качают их с GitHub Releases.

## 2. Продающий лендинг

Аудитория (спецификация, «Для кого»): пользователи персональных AI-агентов (OpenClaw, Hermes, Claude.ai, ChatGPT, Claude Code), чаще всего не программисты. Им нужно понять, зачем это, и поставить gate4ai за минуту.

Содержание главной страницы:

1. **Первый экран:** что это одной фразой («страж для вашего компьютера: AI-агенты получают доступ только к тому, что вы разрешили») и команда установки под ОС посетителя с кнопкой «скопировать».
2. **Проблема:** агентам дают слишком много (залогиненный браузер, все файлы, shell целиком); prompt injection (страница или письмо со скрытой инструкцией) превращается в действия; агенты отчитываются «сделано», хотя ничего не сделали. Первый экран показывает пример: агент хочет `browser.act` на сайте, которого нет в списке разрешённых, gate4ai спрашивает, в подтверждении есть «добавить в разрешённые сайты».
3. **Как работает:** агент → gate4ai (правила: разрешить, запретить или спросить вас) → Браузер, Файлы или коннектор к сайту; два списка доступа владельца — сайты и папки с режимом строки; пароли агент не видит; у каждого действия есть доказательство в журнале.
4. **Сценарии:** списки доступа в YAML (`access: sites:` — «банк читать, на сайте коммуналки спрашивать, остальное закрыто»; `access: folders:` — «заметки дописывать, но не переписывать»), правило по происхождению аргумента («не платить на счёт со страницы») и лимит («не больше 20 действий на страницах в день»). Почту gate4ai не отправляет: письмо на лендинге — только как источник prompt injection.
5. **Работает с вашими агентами:** Claude.ai, ChatGPT, Claude Code, OpenClaw, Hermes (через MCP, CLI, skill); карточки — ссылки на следующий шаг на `/install#next` (мастер `gate4ai ui` подключает агента).
6. **Коннекторы:** Браузер и Файлы встроены (это сказано в заголовке блока), несколько карточек из каталога и ссылка на `/connectors`.
7. **Открытый код и доверие:** исходники на GitHub, лицензии, подписанные релизы и коннекторы, работа локально без облака.
8. **Призыв в конце:** команда установки и подсказка «затем `gate4ai ui` — откроется мастер настройки» (не README).
9. **Подвал:** GitHub, документация, спецификация, контакты, безопасность (`SECURITY.md`).

Утверждения на лендинге должны совпадать с тем, что продукт делает сейчас.

## 3. Каталог коннекторов

- **Источник:** `https://raw.githubusercontent.com/gate4ai/registry/main/index.json` и `index.json.sig`. Сайт проверяет подпись ключом registry (`ed25519:yDcbQuNCGqSqHSt08HdvW5/fNyWRW8FIXtKiL91hqtw=`, тот же, что в README ядра) теми же правилами, что `gate4ai registry check`. Индекс с неверной подписью не показывается: остаётся последний проверенный.
- **Обновление:** периодически (раз в несколько минут) и по запросу из CI registry (webhook) после слияния.
- **`GET /connectors`** — список с поиском по имени, названию и описанию и с фильтром по уровню доверия (`verified`, `publisher`, `community`). Карточка: название, id (моноширинным, если отличается от названия), описание, издатель, уровень доверия, последняя версия.
- **Встроенные Браузер и Файлы** (`browser`, `files`): в магазине их нет — они часть gate4ai, ставить и удалять нечего. Страница каталога без поиска и фильтра показывает их отдельным блоком «Встроено в gate4ai» (название и описание на обоих языках — таблица сайта, не карточки и не ссылки) и объясняет, что коннекторы магазина — WASM-модули без своей сети: на сайты ходят только через Браузер, к файлам — только через Файлы, в границах своих `sites`/`folders` и списков доступа владельца. У коннекторов магазина заголовок — id из registry, описание — из registry.
- **`GET /connectors/<имя>`** — страница коннектора:
  - описание, издатель, уровень доверия и что он значит, лицензия, ссылка на исходники (`repo`);
  - **возможности** (`capabilities`) человеческим языком, каждая один раз: все сайты манифеста (`site <домен>: <режим>`) — одной строкой («ходит на сайты только через ваш Браузер и только на lk.example.org (read) и *.pay.example (read)»), все папки (`folder <путь>: <режим>`) — одной строкой; учётки (`signs in on …`), подвызовы (`action … calls …`), вызовы других коннекторов (`call …`), действия классов выше read (`class … actions: …`) и хранилище — по строке; исходные строки манифеста — только в свёрнутом блоке «Технически» (`<details>`);
  - версии и отозванные версии с причиной;
  - команда установки: `gate4ai connectors install <имя>`, рядом — кнопка «Открыть в gate4.ai» на `http://127.0.0.1:7431/connectors?install=<имя>` с пометкой «если gate4.ai запущен на этом компьютере».
- **`GET /connectors.json`** — тот же индекс как есть, для внешних инструментов.

## 4. Технические требования

- **Язык — Go** (версия из `go.mod`). Один бинарник отдаёт HTML, скрипты установки и API. Стек: стандартная библиотека — `net/http`, шаблоны `html/template` (разбираются при старте, каждый проверяется тестами), шаблоны и статика встраиваются через `embed`; формат индекса registry и проверка его подписи — пакет `sdk-go/registry` (те же правила, что у ядра).
- **Страницы рендерятся на сервере** и работают без JavaScript. JS допускается только для мелочей: «скопировать», поиск в каталоге.
- **Приватность:** без трекеров, сторонних скриптов, шрифтов и cookies. Для продукта о безопасности это часть позиционирования.
- **Языки:** английский (основная аудитория глобальная) и русский; язык выбирается по `Accept-Language`, есть переключатель, отдельные пути `/ru/…`.
- **Скорость:** страница меньше 100 КБ без картинок; адаптивная вёрстка; доступность по WCAG 2.2 AA. Анимации появления при прокрутке выключены при `prefers-reduced-motion: reduce` и при печати (`@media print`): содержимое видно целиком.
- **Репозиторий** — публичный `gate4ai/www`, без лицензии: исходник открыт для чтения, права на использование не передаются; публичный — ради бесплатных минут GitHub Actions ([repo-structure.md](../gate4ai/docs/repo-structure.md)).
- **Эксплуатация:** сайт слушает только HTTP на `127.0.0.1:8080`, TLS (Let's Encrypt) завершает Caddy; служба — контейнер в Compose-проекте (`deploy/compose.yaml`), `/healthz`, логи без IP-адресов посетителей, конфигурация через переменные окружения. Индекс registry и `/latest` — только в памяти, каталога состояния нет.
- **Тесты:** `go test` проверяет маршруты, проверку подписи индекса (верная, неверная, подменённая; здесь и в `sdk-go/registry`; образец `testdata/index.json` подписывается на ходу ключом теста — ключа registry у тестов нет), разбор User-Agent и `/latest`, бюджет страниц, блок встроенных Браузера и Файлов на обоих языках, группировку возможностей, следующий шаг на `/install` и лендинге, переменные установщиков; `install.sh` гоняется в CI на Linux и macOS, `install.ps1` — на Windows; `gofmt`, `go vet`.

## 5. Хостинг

Сайт работает на сервере relay (136.148.221.24) за тем же портом 443. Relay маршрутизирует по SNI: `gate4ai-relay --route gate4.ai=127.0.0.1:8444 --route www.gate4.ai=127.0.0.1:8444` пробрасывает соединения **без расшифровки** ([протокол relay](../gate4ai/relay/docs/protocol.md)) на Caddy из стека наблюдаемости relay — тот же, что обслуживает `grafana.gate4.ai` ([relay/docs/observability.md](../gate4ai/relay/docs/observability.md)).

- **HTTPS завершает Caddy рядом с сайтом, а не relay.** Relay остаётся L4-маршрутизатором и ни для кого не расшифровывает трафик: это тот же принцип, что и для устройств. У relay нет ключей сайта, а сайт не зависит от релизов relay.
- **Сертификаты** на `gate4.ai` и `www.gate4.ai` получает Caddy через ACME **TLS-ALPN-01**: проверка Let's Encrypt приходит на 443 с SNI `gate4.ai` и через маршрут попадает на Caddy. Порт 80 для этого не нужен.
- **Сайт слушает** только HTTP на `127.0.0.1:8080` (Compose-проект `gate4ai-www`, сеть хоста) и не открыт наружу напрямую; Caddy проксирует на него. IP посетителя сайт не видит (relay не передаёт PROXY protocol), это совпадает с требованием не писать IP в логи.
- **Порт 80** занят только во время продления сертификата relay (`certbot --standalone`); редиректа с 80 на HTTPS у сайта нет.
- **DNS:** `gate4.ai` (A 136.148.221.24, AAAA `2a13:7c82:128:48::`) и `www.gate4.ai` (через `*.gate4.ai`) указывают на relay. Сертификат — на оба имени, `www` сайт перенаправляет на `gate4.ai` (308, `GATE4AI_WWW_CANONICAL_HOST`).

## Проверка

- `curl -fsSL https://gate4.ai/install.sh | sh` на чистых Linux (amd64, arm64) и macOS (arm64), а также `irm https://gate4.ai/install.ps1 | iex` на чистой Windows ставят последний релиз и печатают версию; подменённый архив не ставится.
- Главная страница открывается без JS и показывает команду установки под ОС посетителя.
- `/connectors` показывает все коннекторы из подписанного индекса registry, а страница коннектора — его возможности и команду установки.
- Сайт собирается `go build` в один бинарник (образ `ghcr.io/gate4ai/www:<sha>`); тесты и линтеры проходят в CI.
