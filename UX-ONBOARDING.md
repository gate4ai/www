# gate4.ai — UX онбординга: ключевые сценарии и улучшения

> 2026-10-14. Основа: [спецификация](../gate4ai/docs/specification.md), [README ядра](../gate4ai/README.md), [quickstart](../gate4ai/docs/quickstart.md), registry, relay, sdk-go, connectors, [требования к сайту](REQUIREMENTS.md).

## Суть продукта (одной строкой на репозиторий)

| Репозиторий | Что это для пользователя |
|---|---|
| `gate4ai` | daemon + CLI + MCP + Web UI + трей: правила allow / deny / ask для агентов, секреты, журнал |
| `connectors` | почта, файлы, браузер — WASM-модули с объявленными возможностями |
| `registry` | подписанный каталог коннекторов (магазин) |
| `relay` | публичный HTTPS-адрес устройства для облачных агентов без открытых портов |
| `sdk-go` | SDK для авторов коннекторов |
| `www` | сайт: установщики, лендинг, каталог |

Основной пользователь — **не программист** (спецификация, «Для кого»). Сейчас онбординг рассчитан на программиста.

## Главная проблема

От установки до первого действия агента — около 15 шагов в двух терминалах: daemon руками, YAML-файл, временный `store.yaml` ради магазина, установка коннекторов, второй `policy set`, `vault set`, токен, переменная окружения, конфиг MCP. Порядок «магазин → коннекторы → политика» нужно знать заранее, иначе ошибка. Web UI и трей уже есть, но в первом запуске не участвуют.

**Цель:** первое разрешённое и первое подтверждённое действие агента — **за 5 минут без YAML и без второго терминала**.

## Ключевые сценарии

### С1. «Хочу понять, нужно ли мне это» (сайт)

Сейчас: лендинг по требованиям — проблема, схема, сценарии.
Улучшить:
- Первый экран — один живой пример вместо абстракции: «Агент хочет отправить письмо `boss@…` → телефон: *Разрешить / Отклонить*». Короткая анимация или скриншот трея и Telegram.
- Вход по агенту: вкладки «Claude.ai / ChatGPT / Claude Code / OpenClaw» — у каждого свой путь подключения (С4), посетитель сразу видит свой.

### С2. Установка

Сейчас: `curl … | sh`, затем `gate4ai service install` (daemon сейчас и при каждом входе, трей — в автозапуск) или сразу `gate4ai ui`, который в терминале сам запускает daemon в фоне; с `GATE4AI_START=1` установщик включает автозапуск сам. Подробности — [gate4ai/docs/cli-ux.md](../gate4ai/docs/cli-ux.md).
Улучшить:
- Установщик в конце предлагает (Y/n) **автозапуск daemon** (launchd / systemd --user / Run-ключ Windows) и запуск трея — без этого не-программист теряет daemon после закрытия терминала.
- Последняя строка установщика — не список команд, а **одна**: `gate4ai setup` (или сразу открыть Web UI мастера).

### С3. Первая настройка: коннектор + правила

Сейчас: YAML, временная политика ради магазина, ручной порядок шагов, `vault set` через `printf`.
Улучшить:
- **Магазин включён по умолчанию**: официальный registry и его ключ встроены в бинарник; `store` в конфиге — только чтобы заменить. Убирает `store.yaml` и шаг 1 целиком.
- **Мастер первого запуска в Web UI** (и `gate4ai setup` в терминале как текстовый вариант):
  1. «Какого агента подключаем?» → С4.
  2. «К чему дать доступ?» — карточки коннекторов из каталога с возможностями человеческим языком, согласие одной кнопкой.
  3. **Готовые профили-шаблоны** вместо пустого YAML: «Заметки: читать — да, писать — с подтверждением», «Почта: читать — да, отправлять — только контактам из списка, остальное — спросить». Пользователь выбирает папку / адрес, YAML генерируется.
  4. Секреты — поле ввода пароля в Web UI (с подсказкой «пароль приложения Gmail — где взять»), а не `printf | vault set`.
  5. «Куда слать подтверждения?» — трей уже есть; Telegram — по QR / ссылке на бота.
- `policy set` принимает конфиг с ещё не установленными коннекторами: предлагает их поставить, вместо ошибки «неизвестное действие».
- Безопасные умолчания: всё, что не разрешено явно, — `ask`, а не `deny`. Новичок видит запросы и учится, а не получает молчаливые отказы.

### С4. Подключение агента

Сейчас: четыре разных пути (CLI + skill, MCP stdio, `gate4ai run`, relay), каждый — несколько команд; токен копируется руками в JSON.
Улучшить:
- Один экран «Подключить агента» с выбором агента, дальше — готовые действия:
  - **Claude.ai / ChatGPT:** relay регистрируется автоматически при первом выборе облачного агента; показываются `mcp_url` с кнопкой «скопировать», код подключения и 3 скриншота «куда вставить в настройках Claude.ai».
  - **Claude Code / Claude Desktop:** `gate4ai agents add claude-code --install` сам дописывает `mcpServers` в конфиг клиента (с бэкапом); токен не проходит через буфер обмена.
  - **Hermes / OpenClaw:** готовый файл skill одной командой, кладётся в каталог агента.
- В конце — **проверочный вызов**: «Попросите агента: *прочитай todo.md из заметок*». Web UI показывает живую ленту: запрос пришёл → правило → результат. Это момент «aha».

### С5. Первое подтверждение (ask)

Сейчас: уведомление на столе + трей / CLI / Web UI / Telegram.
Улучшить:
- В мастере — **учебное подтверждение**: gate4ai сам присылает тестовый запрос в выбранный канал, пользователь нажимает «Разрешить» и видит, что канал работает.
- В тексте запроса — кто, что, почему спрашиваем (id правила человеческим языком), и кнопка «Всегда разрешать такое» — создаёт правило-исключение без YAML.

### С6. Ежедневная работа: журнал и «почему отказано»

Сейчас: `gate4ai log`, коды выхода 2/3 для агента.
Улучшить:
- Каждый отказ в журнале и уведомлении — с причиной и кнопкой «Разрешить в следующий раз» (предпросмотр правила, симулятор уже есть).
- Агенту при `denied` — понятный текст, который он передаст человеку: «Отправка на этот адрес запрещена правилом X; владелец может разрешить в gate4ai».

### С7. Каталог коннекторов и установка из него

Сейчас (требования): страница коннектора с возможностями и командой `gate4ai connectors install`.
Улучшить:
- Кнопка «Установить» на сайте открывает локальный Web UI (`http://127.0.0.1:7431/connectors/install?name=…`) — если daemon запущен; иначе — команда.
- На странице — 1–2 готовых шаблона правил для этого коннектора («что обычно разрешают»).

### С8. Автор коннектора (sdk-go, registry)

Вторичная аудитория. Сейчас: SDK с «коннектором за пять минут», CONTRIBUTING в registry.
Улучшить: `gate4ai connectors new <имя>` — шаблон проекта; на сайте — раздел «Сделать коннектор» с путём «код → `--dev` установка → PR в registry → уровень `community`».

## Приоритеты

| # | Изменение | Эффект | Цена |
|---|---|---|---|
| 1 | Registry по умолчанию в бинарнике (сделано: в начальной конфигурации daemon) | −1 файл и −2 команды в каждом онбординге | низкая |
| 2 | Автозапуск daemon + трей из установщика (сделано: `gate4ai service install`, `GATE4AI_START=1`; вопрос Y/n в установщике — нет) | daemon не «теряется» | низкая |
| 3 | Мастер в Web UI: агент → коннекторы → шаблон политики → секрет → канал | убирает YAML для не-программиста | средняя |
| 4 | Авто-подключение агентов (MCP-конфиг, relay, skill) | убирает ручной токен | средняя |
| 5 | Учебное подтверждение + проверочный вызов | момент «aha», проверка, что всё работает | низкая |
| 6 | «Всегда разрешать» / «Разрешить в следующий раз» из запроса и журнала | правила растут из практики | средняя |
| 7 | Лендинг по агентам, кнопка «Установить» в каталоге | конверсия с сайта | низкая |

## Метрики онбординга

- Время от `install.sh` до первого успешного вызова агента (цель ≤ 5 мин).
- Доля установок, где был создан хотя бы один агент и одно правило (локально, без телеметрии — опрос / добровольный `gate4ai doctor --report`).
- Число отказов `denied_by_policy` в первый день: высокое — значит, шаблоны слишком строгие.

## Открытые вопросы

- Мастер — только в Web UI или и в `gate4ai setup` (TTY)? Для серверов без графики нужен второй.
- Совмещать ли с умолчанием `ask` для новичков или оставить `deny` (безопаснее, но хуже первый опыт)? Нужно решение — затрагивает модель политик в спецификации.
- Автоправка конфигов чужих клиентов (Claude Desktop и др.) — допустимо ли без явного согласия на каждом шаге.
